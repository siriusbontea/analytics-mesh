Getting started

  1. Open /ui on a node (uv run mesh serve) or the plane (uv run mesh plane).
  2. On the plane, pick a registered node. On a node UI you are already talking to that machine.
  3. Choose a registered analytic (for example top_products) or switch Source to Ad-hoc SQL.
  4. Click Run. The node executes; source data never leaves that node.
  5. Read the preview table. A light bar chart appears when the preview has a label column plus a numeric column.
  6. Download the Parquet artifact if you want the file locally.
  7. Inspect the receipt (who, what, hash). Use Verify chain to check the node’s hash chain.

Analytics work with zero LLM configured. Optional NL→SQL is propose-then-confirm and never auto-executes. To enable Propose SQL locally, serve configs/examples/node-with-models.yaml after Ollama or LM Studio is running; default node.yaml stays LLM-free.

Concepts

  • Node — machine that holds connectors, runs engines, and stores artifacts plus the receipt chain.
  • Connectors / tables — plugins that expose local files or read-only Postgres as named tables. Sensitivity labels come from connector config.
  • Engines — DuckDB is the default for ad-hoc SQL and most analytics; Polars is optional (example: top_products_polars).
  • Analytics registry — versioned YAML + SQL under analytics/. Run by id; latest semver unless you pin a version.
  • Artifacts — Parquet results on the node, capped by the node’s artifacts: store settings.
  • Receipts — hash-chained audit records on the owning node.
  • Principal — identity sent with each run or assist. Policy allowlists decide what that principal may do.

CLI vs UI

The UI is a thin static page over the same HTTP APIs as the CLI. Nothing here is a second execution path.

uv run mesh serve --config configs/examples/node.yaml
# optional Propose SQL: configs/examples/node-with-models.yaml after Ollama is up
uv run mesh analytics list
uv run mesh analytics run top_products
uv run mesh query --sql "SELECT product, SUM(amount) AS total FROM sales GROUP BY product"
uv run mesh receipt <receipt_id> --verify-chain
uv run mesh plane --config configs/examples/plane.yaml
uv run mesh query --url http://127.0.0.1:8090 --node node-b --sql "SELECT 1"

Use the CLI when you want files on disk, pairing, MCP, or scripting. Use this page for interactive preview, chart, and receipt inspection.

Receipts

Each receipt hashes its payload plus prev_hash (SHA-256). The first receipt links to a genesis hash of 64 zeros. Verify chain walks the owning node’s SQLite log.

Recorded: principal, node, action, params (analytic id/version or SQL hash), connector versions, engine, artifact hash, status, and model fields only when assist was used.

Not recorded on the plane: source tables. The plane stores job metadata and pointers (artifact/receipt ids and URLs). The node remains the source of truth for verification.

Plane vs node

  • Node UI (mesh serve, typically http://127.0.0.1:8080/ui) talks only to that node. There is no jobs list.
  • Plane UI (mesh plane, typically http://127.0.0.1:8090/ui) needs a node picker. The plane forwards the run and records a job.
  • Jobs are metadata + pointers. #job=<id> loads that job’s preview and receipt; the artifact is streamed from the owning node, not stored on the plane.
  • Listen / pairing: default bind is 127.0.0.1. For another machine, set Tailscale or LAN addresses in listen_host and plane.public_endpoint — not 0.0.0.0. Example YAML keeps demo-pair-token for localhost only; set MESH_PAIR_TOKEN beyond that.

Deep links: #help or #help=receipts open this drawer; #job= opens a plane job result.

Policy

YAML allowlists (example: configs/examples/policy.yaml) name principals and what they may use: connectors, analytics, nodes, row/time caps, and local_only vs allow_frontier. If policy_path is omitted, the node allows every principal (earlier milestone behavior).

Denied run_* / assist calls return HTTP 403 and append a failed receipt. Sensitivity labels on connectors are informational metadata shown in this UI; they do not replace the allowlist.

NL→SQL assist is propose-then-confirm. Propose SQL never auto-executes. Confirm and run proposed SQL is a separate, explicit step. Assist is optional; analytics still work with zero LLM.

MCP

The MCP adapter is a client of the node or plane, not a second engine. Shipped tools are analytics-only:

  • list_analytics
  • run_analytic
  • get_receipt

Optional extras: list_connectors, list_nodes. There is no run_query, raw SQL, shell, or connector-credential tool. Tools call the same policy-gated HTTP APIs as this UI. Start with uv run mesh mcp --url http://127.0.0.1:8080 --principal local.
